# Verification results — Quartz eight-layer Q/V LoRA (28 October 2026)

This is an **experimental** verification of the 4-step rank-2
Q/V LoRA trained on a Samsung S26 Ultra against a frozen
Qwen2.5-0.5B GGUF. It is not a claim of full-parameter fine-tuning
or general intelligence.

## Independent PC test

The read-only PC harness (verified native Quartz on frozen Qwen)
tested six fresh, balanced sentiment prompts that do not exactly
match any train/internal-holdout/challenge fixture prompt.

- Model integrity: SHA-256 matches the pinned frozen GGUF.
- Adapter integrity: SHA-256 matches the phone-trained four-step adapter.
- All 32 F32 safetensors matrices valid; both Q and V have nonzero
  learned weights at all eight transformer layers 16–23.
- All evaluated target labels are one GGUF token.
- Exactly 18 unique prompts across original training/heldout,
  fresh, composition and unrelated tests.
- Fresh labels: 5/6 individual prompts improved.
- Original model mean CE 0.6072431;
  with adapter mean CE 0.3144017 (48.2% lower).
- Deliberately wrong/opposite labels: mean CE was
  4.4871334 before versus 5.8746958 with the adapter. The negative
  control has the expected *average* degradation.
- However, per-prompt **correct-vs-incorrect preference margin**
  improved in only 4/6. This is a specific weakness worth tracking,
  not evidence of perfect sentiment classification.
- Compositional/negation challenges: 5/6 improved. The
  "Review: not terrible" target became *worse*:
  CE 0.4415 -> 1.3466. Not a clean negation generalisation result.
- Unrelated target completions: none of the three lost >0.5
  cross-entropy; one was mildly worse (+0.1243).
- Native GGUF adapter loader rejected deliberately wrong-base
  metadata and a truncated safetensors payload.
- Frozen model and saved adapter had unchanged hashes after evaluation.
- Result for the original PC-run acceptance set: PASS, but with
  meaningful WARN diagnostics. Later harness revisions distinguish
  PASS_WITH_WARNINGS from an entirely clean PASS.

## Independent Samsung S26 test

Same adapter and six fresh prompts, in a fresh native Quartz process
on-device. PC harness/test data were not used to precompute logits.

- Six examples; 5/6 improved.
- Base mean CE: 0.6072459.
- Adapted mean CE: 0.3144062.
- Battery 50% -> 50% (integer % readings).
- Android thermal 0 -> 0.
- Before/after SHA-256 for both GGUF and adapter match.
- Phone JSON: verification-s26-20261028T191730Z.json
  Phone run log: verification-s26-20261028T191730Z.log

## Cross-device parity

A separate comparator checked matching pinned artifacts and metrics.
- Absolute mean base-CE difference: 0.0000028.
- Absolute adapted-CE difference: 0.0000045.
- Both < 0.0001 acceptance tolerance.
- Sample count, individual improvement count (5/6), model SHA,
  adapter SHA, battery and thermal safety checks matched.
- Cross-device consistency status: PASS.

This is consistency between **trusted connected runtimes** and
not cryptographic trusted-hardware attestation.

## Reproducibility evidence and next gates

Full native evaluation logs, a versioned JSON report, phone JSON
and cross-device comparator result live under an ignored run directory:

  verification/runs/20261028T191417Z-bc2fe0a7/

The more expensive full verification mode is separately runnable
with two independent deterministic train repeats, a real-model
finite-difference test, the complete Rust suite and an optional
repeat independent evaluation:

  python3 verification/verify.py --mode full \
    --repeat-train --repeat-evaluation --timeout-seconds 220

**Limitations:** only two training examples in the original run, one
internal held-out example, six fresh sentiment examples, heavily
templated binary labels, and no full-sequence supervision. The
underlying 0.5B GGUF remains completely unchanged. A correctness
harness cannot alone establish production-grade generalisation.


## Full verification harness run

The first end-to-end full-mode run is archived at:

  verification/runs/20261028T192134Z-0d106988/

- Result: **PASS_WITH_WARNINGS** (29 recorded gates, no required-gate
  failures, two meaningful diagnostic warnings).
- Total host run: 403.4 seconds.
- First and repeated six-example evaluation: exactly the same
  per-prompt CE to the precision printed by Quartz (zero measured
  repeat-process drift).
- Two deterministic, *fresh*, two-layer trainings (same seed/data)
  generated **byte-identical** 45,939-byte safetensors files.
  Both SHA256 digests:
  d9dd7e225b427745d8360300dba98b02a6b262cd9de7cb9e39f0dd5dd7f326ee
- Native numerical gradient check passed on all eight Q/V A/B
  matrix groups at both ends of the two-layer suffix.
- 117 Quartz Rust tests passed, 0 failed, 11 ignored.
- Native wrong-base and truncated adapter failure checks passed.
- Frozen base and selected phone-trained adapter were unchanged.
- The full report was compared with the independent S26 JSON: all
  cross-device checks passed.

The first full run began when the implementation's costly repeated
training and numerical-gradient gates used **two layers**. The final
harness source was subsequently extended to use the configured
eight-layer suffix for those gates. An eight-layer real-GGUF
finite-difference check had already passed independently as part
of Stage 2 and is retained in the original Quartz experiment logs.
Do not misrepresent the first full-mode run as eight-layer
deterministic repeat-training evidence.

The fixture-manifest pin was added while this long verification run
was underway. A subsequent independent audit of the same known
adapter and fixtures confirmed all four pinned SHA256s. The
current harness source enforces that manifest for future runs.
